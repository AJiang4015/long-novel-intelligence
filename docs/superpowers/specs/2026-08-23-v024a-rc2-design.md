## 1. 背景与问题（RC2）

Job 880c9f1c 诊断发现：V0.2.4 的 hygiene 过滤**只阻止注册，未阻止输出**。

- `_resolve_name()` 对硬过滤 mention（COLLECTIVE/INVALID）返回 `(name, False)`——不注册，但**返回原名**。
- `resolve()` 的 `for c in result.characters: resolved_chars.append({"name": do_name(c.name)})` **无条件 append** → 被过滤名进入 `resolved.characters`。
- `merge_extractions()` 从 `resolved.characters` 建 Person → 被过滤名**写入 Neo4j**。

实证（确定性实验 diag_filter_leak.txt）：`两个儿子` 被 `collective_filtered` 计数，但 `out.characters == ['两个儿子']` 且 `merged.persons` 含 `两个儿子`。

## 2. 目标

被硬过滤 mention（COLLECTIVE/INVALID）在 resolve 输出层**彻底剔除**，不得进入任何下游状态/数据：

```
resolved.characters / resolved.relationships
known / _index / canonical_aliases / merge_evidence
MergedGraph / Neo4j
```

## 4. 设计

### 4.1 `resolve()` characters 循环剔除

在 `for c in result.characters:` 循环中，硬过滤 name **不 append**：

```python
from app.pipeline.hygiene import is_hard_filtered
for c in result.characters:
    if is_hard_filtered(c.name):
        continue            # RC2：被硬过滤 mention 不进入 resolved.characters
    resolved_chars.append({"name": do_name(c.name)})
```

**注意**：`_resolve_name` 返回契约不变（不引入空串/哨兵）；硬过滤名不进 pending（`do_name` 不会被调用）。同时 `_current_categories` 仍记录它（无害），hygiene_stats 计数已在 `_resolve_name` 的硬过滤分支（若 do_name 未被调用，计数需在循环前或循环内处理——见 §4.3）。

### 4.2 relationships 循环：任一 endpoint 硬过滤 → 丢弃整条关系

```python
for r in result.relationships:
    if is_hard_filtered(r.source) or is_hard_filtered(r.target):
        continue            # RC2：任一 endpoint 为硬过滤 mention → 丢弃整条关系
    src = do_name(r.source)
    tgt = do_name(r.target)
    resolved_rels.append({...})
```

### 4.3 计数位置（保持 stats 正确）

当前 `hygiene_stats` 计数在 `_resolve_name` 硬过滤分支（L158-162）。若循环跳过（不调 do_name），需把计数移到循环外/循环内独立处理，保证 `collective_filtered` / `invalid_filtered` 仍正确累加。建议：

```python
from app.pipeline.hygiene import classify_mention, is_hard_filtered
for c in result.characters:
    if is_hard_filtered(c.name):
        if classify_mention(c.name) == MentionCategory.COLLECTIVE:
            self.hygiene_stats["collective_filtered"] += 1
        else:
            self.hygiene_stats["invalid_filtered"] += 1
        continue
    resolved_chars.append({"name": do_name(c.name)})
```

（`_resolve_name` 的硬过滤分支保留作为防御，但正常路径不会到达。）

### 4.4 merge_evidence 保护

被硬过滤 mention 不进 pending → 不进 merge_evidence 的 mention/candidates/pair（现有 `_recall` 排除 + pending 不产生）。但为防御，`merge_evidence` 收集循环（L90-102）已按 `candidates ∩ established` 过滤，硬过滤 canonical 已在 `_recall` 排除——RC2 的循环剔除进一步保证硬过滤 mention 本身不进 pending，双保险。

## 5. 数据流（修复后）

```
extract(LLM, category) 
  → hygiene classify（COLLECTIVE/INVALID 标记）
  → resolve() characters 循环：硬过滤 → 跳过（+计数），不进 resolved_chars
  → resolve() relationships 循环：任一 endpoint 硬过滤 → 丢弃整条关系
  → resolved ExtractionResult（无硬过滤名）
  → merge_extractions → MergedGraph（无硬过滤 Person）
  → apply_aliases → apply_merges → upsert_graph（Neo4j 无硬过滤 Person）
```
